# GoldDonchianBreakout.mq5 (MT5 EA)

`reports/trading_plan.md` で検証したルール(ゴールド1時間足・ドンチアン20ブレイクアウト・ATR損切り1.5x/利確3.0x・最大保有20本・リスク0.5%)を**そのまま**自動売買化したMT5用EA。

## 先に読んでほしいこと

**このEAは「検証で優位性が証明された手法」を自動化したものではありません。** `reports/validation_report.md`の通り、実質期待値+0.054R・95%信頼区間[−0.052, +0.160]で、**統計的には未証明**です。自動化はルール通りの執行を機械的・感情抜きで行うためのツールであり、手法そのものの正しさを保証しません。手法が機能しなければ、人間の判断が入らない分、損失も機械的に積み重なります。

**実弾投入の前に`reports/trading_plan.md`の合否ゲート(スプレッド確認 → デモ100トレード → 合否判定)を必ず通してください。** このEAはそのフォワードテストを行うための道具として使うのが正しい使い方です。

## 実装しているルール

| 項目 | 値 | 対応するPythonコード |
|---|---|---|
| 銘柄・時間足 | ゴールド・1時間足(H1) | `data/gold_1h_730d.csv` |
| エントリー | 直前の確定足の終値が、その前20本の高値/安値レンジを上抜け/下抜け | `strategies.py: donchian_breakout()` |
| 損切り | シグナル確定足のATR(14) × 1.5 | `backtest.py: run_backtest(stop_atr=1.5)` |
| 利確 | シグナル確定足のATR(14) × 3.0 | `backtest.py: run_backtest(reward_atr=3.0)` |
| 最大保有 | 20本(約20時間)で未決着なら成行決済 | `backtest.py: max_hold=20` |
| 同時ポジション | 1つのみ | — |
| リスク | 口座残高 × 0.5%(入力で変更可) | `reports/trading_plan.md` の推奨値 |
| サーキットブレーカー | 累計−10Rで新規エントリー停止 | `reports/trading_plan.md` |
| ニュースフィルター | 米国ハイインパクト指標の前後60分は新規エントリーしない | `src/fundamentals.py` と同じ考え方(MT5組み込みの経済指標カレンダーを使用。ブローカーによっては非対応) |

パラメータを変える場合は、必ず先に`src/`のPythonバックテストで同じ変更を検証してから反映してください。EA側だけで数値をいじるのは、これまで繰り返し否定してきた「後付けの最適化」そのものです。

## 導入手順

1. MetaEditorで`GoldDonchianBreakout.mq5`を開き、**コンパイル**する(このリポジトリの環境にはMT5がないため、コンパイルエラーが出ないかは実機で確認してください)。
2. **必ずストラテジーテスターで先にテストする**。ブローカーのゴールドシンボル(XAUUSD、GOLDなど)、期間はできるだけ長く、モデルは「本物のティック」を推奨。
3. テスターの結果を`reports/long_history_results.csv`のゴールド・ドンチアン・ブレイクアウトの行(614件, 勝率38.6%, 実質期待値+0.054R)と見比べる。**完全一致はしません**(ブローカーのヒストリーはYahoo Financeと異なるスプレッド・値動きのため)が、大きくかけ離れている場合は、EAのロジックかブローカーのデータに問題がある可能性があるので原因を確認する。
4. 問題なければ**デモ口座**で最低100トレード分運用し、`GoldDonchianBreakout_TradeLog.csv`(MT5の「共有フォルダを開く」→`MQL5/Files/`に出力される)を`reports/`の検証結果と比較する。
5. デモで期待値がプラスと確認できて初めて、`InpRiskPercent`を小さい値(0.5)にしたまま実弾を検討する。

## 入力パラメータ

- `InpRiskPercent`: 1トレードあたりのリスク%。**2%を超えないこと**(`reports/montecarlo_results.csv`参照。リスクを上げても資金が増える確率は上がらず、減少幅だけが増える)。
- `InpMaxDrawdownR`: サーキットブレーカーの閾値。累計R(グローバル変数で永続化、端末再起動をまたいで保持)がこの値を下回ると新規エントリーを自動停止する。
- `InpResetCircuitBreakerOnInit`: サーキットブレーカー停止後、原因を確認した上で再開する場合のみ`true`にしてEAを再読込し、その後`false`に戻す。
- `InpUseNewsFilter` / `InpNewsBufferMinutes`: MT5組み込みの経済指標カレンダーを使い、米国ハイインパクト指標の前後(既定60分)は新規エントリーを見送る。カレンダーがブローカーで使えない場合はOnInit時にログへ警告が出るので、`false`に切り替える。

## 既知の制約

- MT5のバックテスト(ストラテジーテスター)は、ブローカーが提供するヒストリーデータを使うため、このリポジトリのPython検証(Yahoo Finance)と**厳密には一致しません**。傾向が大きく違わないかの確認に使ってください。
- スプレッド・スリッページはブローカーの実際の執行に依存します。`reports/validation_report.md`にある通り、ゴールドの往復スプレッドが**約$1.58を超えると、この手法の統計的な優位性(未証明ではあるが)は完全に消滅**します。自分の口座の実スプレッドを必ず確認してください。
- 経済指標カレンダー機能は、全てのブローカー・全てのMT5ビルドで動くとは限りません(ベストエフォート)。
